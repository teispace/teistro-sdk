The catalogue members a text may name (`03-design/lexicon.md` §1.3), answered as canonical JSON: `{matches}`, each match `{start, end, text, candidates}` in the text's order, `start` and `end` counted in Unicode scalar values, and each candidate `{key, via}`, `via` the forms whose fold the span's is. A span that may name several members answers every one of them.

`request_json` is `{"text"}`, with `"locale"` (whose chain's names are searched; every loaded locale's when left out) and `"kinds"` (every kind when left out). A key it does not read or a kind no member's name has is `INVALID_ARG`, named under `lookup`; a locale no loaded one answers is `UNSUPPORTED`.

<Tab value="C">

```c
ts_status ts_intl_lookup(const ts_context * context, const char * request_json, ts_string * out_json);
```

</Tab>

Reached from `intl.lookup` on the surface; [the surface](/docs/surface) says how each binding spells a path.

## Parameters

| name | type | role | what it carries |
|---|---|---|---|
| `context` | `const ts_context *` | the handle | — |
| `request_json` | `const char *` | a string read | — |
| `out_json` | `ts_string *` | receives a string | — |

## What it hands back

`json`. The call returns a status; a status other than `TS_STATUS_OK` means nothing was written.

## Safety

`context` must be a live handle; `request_json` NUL-terminated; `out_json` valid for a write.

Declared in `crates/ffi/src/intl.rs`.
