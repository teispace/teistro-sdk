The loaded locale a tag means, by RFC 4647 lookup, lent until the next call on the context: `ne` is `ne-Deva-NP`. Nothing changes, and `ts_intl_set_locale` selects the same one.

# Errors

`UNSUPPORTED` naming the loaded locales, as `ts_intl_set_locale`.

<Tabs items={['C']}>
<Tab value="C">

```c
ts_status ts_intl_lookup_locale(const ts_context * context, const char * locale, ts_str * out_locale);
```

</Tab>
</Tabs>

Reached from `intl.lookup_locale` on the surface; [the surface](/docs/surface) says how each binding spells a path.

## Parameters

| name | type | role | what it carries |
|---|---|---|---|
| `context` | `const ts_context *` | the handle | — |
| `locale` | `const char *` | a string read | — |
| `out_locale` | `ts_str *` | receives a lent string | — |

## What it hands back

`locale`. The call returns a status; a status other than `TS_STATUS_OK` means nothing was written.

## Safety

`context` must be a live handle; `locale` a NUL-terminated string; `out_locale` valid for a write.

Declared in `crates/ffi/src/intl.rs`.
