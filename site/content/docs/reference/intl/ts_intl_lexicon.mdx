Every catalogue member's names in a locale, romanised forms too (`03-design/lexicon.md` §1), answered as canonical JSON: `{locale, entries}`, each entry `{key, forms}` and each form `{form, text, locale}`, the form `name`, `prose`, `short`, `iast`, any the locale adds, or `romanised`, and `locale` the one in the chain that gave it.

`request_json` is `{}`, with `"locale"` (a loaded tag or one that means one, `ne`; the context's when left out) and `"kinds"` (`["tithi", "nakshatra"]`; every kind when left out). A key it does not read or a kind no member's name has is `INVALID_ARG`, named under `lexicon`; a locale no loaded one answers is `UNSUPPORTED`. The lexicon is built the first time a locale is asked for and kept on the context.

<Tab value="C">

```c
ts_status ts_intl_lexicon(const ts_context * context, const char * request_json, ts_string * out_json);
```

Reached from `intl.lexicon` on the surface; [the surface](/docs/surface) says how each binding spells a path.

## Parameters

| name | type | role | what it carries |
|---|---|---|---|
| `context` | `const ts_context *` | the handle | — |
| `request_json` | `const char *` | a string read | — |
| `out_json` | `ts_string *` | receives a string | — |

## What it hands back

`json`. The call returns a status; a status other than `TS_STATUS_OK` means nothing was written.

## Safety

`context` must be a live handle; `request_json` NUL-terminated; `out_json` valid for a write.

Declared in `crates/ffi/src/intl.rs`.
