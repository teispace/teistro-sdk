What this build is, as a static NUL-terminated JSON object: the SDK version, the ABI and catalogue versions, the commit and whether its tree was clean, the profile, the target, whether debug assertions and optimisation are on, the sanitizer if any, and the compiler.

A binding reads it when it loads the library and refuses one that is not the build its own half was generated for (`02-architecture/07-binding-architecture.md`, "Loading and identity"). The document is written when the library is compiled, so it costs nothing to ask and cannot disagree with the library it describes.

```c
const char * ts_build_info(void);
```

No operation of a context calls this by name. A binding calls it itself, opening the library, freeing what the library handed back or reading an error, or offers it outside a context, as the library's version and the fixed-day arithmetic are.

The call takes no arguments.

Declared in `crates/ffi/src/lib.rs`.
