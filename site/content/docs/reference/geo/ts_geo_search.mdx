The places matching a name, best first, as the context's geo provider ranks them, answered as canonical JSON: a list of `{place, score}`, each place `{id, name, nameLang, label, kind, level, code, latitudeDeg, longitudeDeg, population, parents}`. `score` compares within one query.

`request_json` is `{"query", "focus", "limit", "lang"}`: the text as typed in any script the provider's data holds (`"Name, Parent"` puts the named parent's places first), an optional focus `{latitudeDeg, longitudeDeg, scaleM}` preferring places near it, at most `limit` places (1 to 100, default 10), each named in the BCP 47 `lang`. An empty query, a limit out of range or a malformed tag is `INVALID_ARG` on its field; a context with no provider is `CAPABILITY` on `geo`; a provider built without search is `CAPABILITY` on `search`.

## What it hands back

`json`. The call returns a status; a status other than `TS_STATUS_OK` means nothing was written.

## Safety

`context` must be a live handle; `request_json` NUL-terminated; `out_json` valid for a write.
