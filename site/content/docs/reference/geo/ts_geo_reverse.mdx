The named places nearest a point and the admin units holding it, from the context's geo provider, answered as canonical JSON `{near, admin}`: `near` the nearest places, nearest first, each `{place, distanceM, bearingDeg, inside}`; `admin` the units holding the point coarse to fine, each a place as `ts_geo_search` answers one. A level the provider's data holds no outline for is absent, never a refusal.

`request_json` is `{"latitudeDeg", "longitudeDeg", "limit", "lang"}`, `limit` 1 to 100 (default 5). A point out of range is `INVALID_ARG` on `latitudeDeg` or `longitudeDeg`; a context with no provider is `CAPABILITY` on `geo`.

## Parameters

| name | type | role | what it carries |
|---|---|---|---|
| `context` | `const ts_context *` | the handle | — |
| `request_json` | `const char *` | a string read | — |
| `out_json` | `ts_string *` | receives a string | — |

## What it hands back

`json`. The call returns a status; a status other than `TS_STATUS_OK` means nothing was written.

## Safety

`context` must be a live handle; `request_json` NUL-terminated; `out_json` valid for a write.

Declared in `crates/ffi/src/geo.rs`.
