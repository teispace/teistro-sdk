A chart layout this context can draw in, shipped or registered, as its JSON row: the record `options.layouts_json` takes. Read a shipped row, give it a key of its own, change what differs and register it (`03-design/chart-geometry.md` §7f). `key` is the layout's key, bare (`NORTH_INDIAN`) or full (`chart_layout.NORTH_INDIAN`); an unknown one is `INVALID_ARG` with the keys the context knows as the hint.

## Parameters

| name | type | role | what it carries |
|---|---|---|---|
| `context` | `const ts_context *` | the handle | — |
| `key` | `const char *` | a string read | — |
| `out_json` | `ts_string *` | receives a string | — |

## What it hands back

`json`. The call returns a status; a status other than `TS_STATUS_OK` means nothing was written.

## Safety

`context` must be a live handle; `key` a NUL-terminated string; `out_json` valid for a write.

Declared in `crates/ffi/src/chart.rs`.
