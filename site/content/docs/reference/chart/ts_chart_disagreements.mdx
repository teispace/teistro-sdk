**Where two charts disagree** (`03-design/chart-disagreements.md`): the first chart founded under `context`, the second under `other`, and answers with `{value, provenance}` as canonical JSON, sealed by the first chart's provenance with the whole request as its input, every catalogue member a full key. Pass `context` again as `other` to compare two births under one setting.

`value` is `{otherProfile, otherSettingsHash, at, compared, lagna, grahas, nakshatra, dashas, yogas}`: `lagna` null unless its sign differs, else `{first, second}`, each side `{sign, longitudeDeg, degreesInSign}`; `grahas` each graha both place whose sign differs, as `{graha, first, second}`; `nakshatra` null unless the Moon's star or pada differs, else `{first, second}`, each `{nakshatra, pada, longitudeDeg}`; `dashas` each level both carry whose running lord differs, `{system, level, first, second}`, each side `{lord, sign, interval}` or null; and `yogas` each rule one side holds and the other does not, or with another status, `{rule, category, first, second}`. `compared` counts the facts read.

`request_json` is `{"first", "second", "at"}`: `first` a chart request of one birth (`instant`, `latitudeDeg`, `longitudeDeg`, `altitudeM`, `utcOffsetSeconds`, and any `dashas` and `rules` record), `second` another, optional (the first's birth again), and `at` the UTC Julian day the running dasha lords are compared at (each birth's own when left out). A side naming no dasha system is read under Vimshottari. A key it does not read, a chart request its reader refuses or one of more than one birth is `INVALID_ARG`, named under `disagreements`; a null `other` is `INVALID_ARG` naming `other`. Either context without an ephemeris is `CAPABILITY`.

## Parameters

| name | type | role | what it carries |
|---|---|---|---|
| `context` | `const ts_context *` | the handle | — |
| `other` | `const ts_context *` | the handle | — |
| `request_json` | `const char *` | a string read | — |
| `out_json` | `ts_string *` | receives a string | — |

## What it hands back

`json`. The call returns a status; a status other than `TS_STATUS_OK` means nothing was written.

## Safety

`context` and `other` must be live handles; `request_json` NUL-terminated; `out_json` valid for a write.
