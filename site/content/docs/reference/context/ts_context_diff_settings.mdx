**Where two contexts' settings part** (`settings.diff`), as canonical JSON: `{profile, otherProfile, settingsHash, otherSettingsHash, knobs}`, each knob on which `context`'s settings and `other`'s differ as `{knob, value, otherValue, moves, effect}`, `moves` and `effect` as `ts_context_explain_settings` gives them, the note in `context`'s locale; no knobs when the two hash alike. `SKY` is what a calendar comparison calls a model difference, `RULE` a rule difference.

`request_json` is `{"knobs"}` as `ts_context_explain_settings` reads it, every knob when left out. A null `other` is `INVALID_ARG` naming `other`.

<Tabs items={['C']}>
<Tab value="C">

```c
ts_status ts_context_diff_settings(const ts_context * context, const ts_context * other, const char * request_json, ts_string * out_json);
```

</Tab>
</Tabs>

Reached from `(root).diff_settings` on the surface; [the surface](/docs/surface) says how each binding spells a path.

## Parameters

| name | type | role | what it carries |
|---|---|---|---|
| `context` | `const ts_context *` | the handle | — |
| `other` | `const ts_context *` | the handle | — |
| `request_json` | `const char *` | a string read | — |
| `out_json` | `ts_string *` | receives a string | — |

## What it hands back

`json`. The call returns a status; a status other than `TS_STATUS_OK` means nothing was written.

## Safety

`context` and `other` must be live handles; `request_json` NUL-terminated; `out_json` valid for a write.

Declared in `crates/ffi/src/context.rs`.
