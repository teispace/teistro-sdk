title: A birth chart

A birth chart is the scenario the SDK exists for, and it is not one call.
A record as people write one — a Bikram Sambat date, a clock time, a
place — becomes an **instant** through the zone's own history, the chart
is **founded** at that instant and place, and every section a reader
wants is asked for by name and computed in the same crossing.

## From the record to the instant

```js title="bindings/node/example/birth_chart.mjs"
const ctx = new Context({
  profile: 'nepali-default',
  locale: 'ne-Deva-NP',
  ephemeris: 'BUILTIN',
});
// …
const birthDay = date(Calendar.BikramSambat, 2042, 9, 17);
const gregorian = ctx.calendar.convert(birthDay, Calendar.Gregorian);
// …
const when = ctx.time.resolve(at(birthDay, { hour: 0, minute: 20 }), ianaZone('Asia/Kathmandu'));
```

The record sits on the day Nepal moved from +05:30 to +05:45, so a fixed
offset would be wrong by a quarter of an hour. The resolution says which
rule it used and from which tzdb, and a stored chart keeps both.

In Python, Dart, Java and Rust a latitude is its own type, checked for
range when it is made, so it cannot be passed where a longitude is
wanted, in whichever order a constructor takes them.

The SDK's canonical frame is tropical, because that is what an ephemeris
computes. The profile asks for the sidereal zodiac, Lahiri's ayanamsha and
the Moon seen from Kathmandu rather than from the Earth's centre, and the
founder completes the frame and stamps every step it applied. Positions
asked for directly would not know the profile wants a topocentric Moon,
which moves it most of a degree. The example prints:

tropical chart has no ayanamsha, not one of nought.

## A birth with no recorded time

The commonest data problem in the field, and the SDK does not pick a time
for you. `whenUnknown` says the time is unknown, and what happens next is
the profile's `time.unknown_time` policy. By default there is none, so the
call is refused with a hint naming the choices:

```js title="bindings/node/example/birth_chart.mjs"
const noTime = whenUnknown(birthDay);
for (const policy of [undefined, 'NOON', 'MIDNIGHT']) {
  const scoped = new Context({
    profile: 'nepali-default',
    locale: 'ne-Deva-NP',
    ephemeris: 'BUILTIN',
    settings: policy ? { time: { unknown_time: policy } } : undefined,
  });
```

```text output="birth_chart"
refuse    BIKRAM_SAMBAT 2042-09-17 (time unknown) has no time of day
          hint: give a time, or choose NOON, MIDNIGHT or SUNRISE as the unknown-time policy
NOON      JD 2446431.760417  time known false  TIME_UNKNOWN_FALLBACK
MIDNIGHT  BIKRAM_SAMBAT 2042-09-17 (time unknown) does not exist in Asia/Kathmandu: the clocks jumped from +05:30 to +05:45
          hint: choose SHIFT_FORWARD as the gap policy to move the time past the jump
```

MIDNIGHT is refused for this record's own reason: the clocks jumped at
midnight on that date, so 00:00 never happened in Kathmandu. NOON answers
and says so twice, so a stored chart can never quietly claim a birth time
it never had.

## The whole reading in one call

A reading is what comes after the placements: the divisional charts, the
houses, what each graha *is* rather than where it stands, which grahas
look at which, the derived points and a drawing. Each is a section asked
for by name and computed from the same founded chart, so asking for all
of them costs one call and asking for none costs nothing:

```js title="bindings/node/example/chart_reading.mjs"
const chart = ctx.chart.found({
  instant: when.instantJdUtc,
  place: { latitude: 27.7172, longitude: 85.324, altitude: 1400 },
  utcOffsetSeconds: when.offsetSeconds,
  vargas: [Varga.D9, Varga.D10],
  aspects: true,
  points: true,
  houses: true,
  state: true,
  drawings: [{ layout: ChartLayout.NorthIndian, varga: Varga.D9 }],
});
const [navamsha, dasamsha] = chart.vargas;
```


- **Vargottama is a comparison, not a flag**: a graha whose navamsha sign
  is the sign it stands in. The layer gives both signs.
- **A dignity and a house are different questions**, answered by
  different sections: `states` says how a graha fares in its sign,
  `bhavas` who rules a house.
- **The drishti are ragged**: how many there are depends on where the
  grahas stand, not on how many grahas there are.
- **A drawing is geometry, not pixels**: each cell's outline in a unit
  square, the sign and house it shows and the grahas in it, so any
  renderer draws the same chart.

## When the time is known only roughly

A record that says "some time before dawn" is narrowed by the lagna,
which changes sign every couple of hours. A rectification pass wants many
charts at one place, and `foundMany` founds them in one crossing: the
settings are resolved once, the solar model built once, and every
instant's day is reckoned against the same sunrise.

```js title="bindings/node/example/rectification.mjs"
const instants = Array.from({ length: count }, (_, i) => start.instantJdUtc + i * step);

const charts = ctx.chart.foundMany({
  instants,
  place,
  utcOffsetSeconds: start.offsetSeconds,
  kind: ChartKind.Natal,
});
```
