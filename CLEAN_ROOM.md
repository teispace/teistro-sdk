# Clean-room policy

Teistro SDK is published under the Apache License 2.0, and its accuracy
claims rest on classical texts and observational references. Both facts
depend on where the code and the data came from. This page says what may
be taken from each kind of source, what may never be, and how the
repository proves it. It is binding on every contributor; the reasoning is
in `docs/08-decisions/adr-0018-evidence-ranks-and-mark-and-continue.md`
and `adr-0019-clean-room-and-licence-containment.md`.

## Sources, by rank

| rank | source | what it settles |
|---|---|---|
| 1 | primary texts (Brihat Parashara Hora Shastra, Saravali, Phaladeepika, Jataka Parijata, Uttara Kalamrita, the Jaimini Sutras, Tajika Neelakanthi, Krishnamurti's readers, Raman's and Narasimha Rao's textbooks) and observational references (JPL Horizons and DE files, IERS, the NASA eclipse canon, official almanacs) | what a rule, a table or a position is |
| 2 | the baseline engine (ours; production-validated against its cited corpus) and Teimeris (ours; measured against Swiss Ephemeris) | how a rule or a computation is implemented; reference values with a tolerance |
| 3 | third-party implementations and their documentation (PyJHora, VedAstro, Swiss Ephemeris) | that a feature exists and belongs in scope; reference values for cross-checks |

A disagreement between a rank-3 source and a rank-2 source is a question,
recorded in `docs/01-research/feature-universe/19-verification-cruxes.md`,
never a correction. Only a rank-1 source corrects a rank-2 value.

## What may be taken from each source

| source | licence | may be taken | may never be taken |
|---|---|---|---|
| primary texts | facts are not copyrightable; translations are | verse numbers, lord orders, year counts, tables, applicability conditions, cited by chapter and verse | translated prose reproduced into rule data |
| the baseline engine | Teispace's | ideas, rule data, corpora, constants; implementations are re-derived over the SDK's kernels | a mechanical transliteration of its class structure |
| Teimeris | Teispace's | signatures, conventions, reference values | |
| PyJHora | AGPL-3.0 | the existence of a feature; published reference values with a citation | code, constant tables, comments, algorithms read from the code |
| VedAstro | MIT | code and tables with attribution retained | a table as a substitute for a classical citation |
| Swiss Ephemeris | AGPL-3.0 or Professional | its documentation as a description of its behaviour; reference values through Teimeris or a licensed copy in a dev-only crate | code; any presence in a publishable crate's dependency graph |
| ERFA | BSD-3-Clause | a faithful Rust port with the notice kept in `NOTICE` and a function-by-function provenance table | the name SOFA for the port |
| VSOP87, ELP/MPP02, JPL DE | published scientific data; JPL data is public domain | coefficient tables generated by our tool with citations | another implementation's truncation or code |
| CLDR and tzdb | Unicode licence; public domain | data | |

## Rules

1. No code, constant table or comment is copied from a copyleft source.
   Ever. A feature learned from one is implemented from a rank-1 text and
   cited in the data.
2. A table row, rule or variant that has no rank-1 citation does not ship.
   It is a registered identifier with no implementation: requesting it
   returns `UNSUPPORTED` with the reason `unsourced`, never a silent
   default (the "mark and continue" rule).
3. Reference values from any implementation may be used to verify ours;
   the fixture records the number, the tool and its version, never the
   code that produced it.
4. Dependencies are an allow list (`deny.toml`): MIT, Apache-2.0, BSD,
   ISC, Zlib, 0BSD, Unicode, CC0 and Unlicense. GPL, LGPL, AGPL, SSPL and
   MPL are denied in every publishable crate's graph, including its
   dev-dependencies. Oracles under other terms live in crates marked
   `publish = false` or in recorded fixtures.
5. Ephemeris adapters for licensed engines (Teimeris, Swiss Ephemeris)
   are published separately under their own terms and depend on the SDK,
   never the reverse. The SDK builds and passes its tests with no adapter
   present.
6. Ported permissive code keeps its notice and carries a provenance table
   (source function, our function, test, version ported from).

## How the repository proves it

- `cargo deny check` runs in the fast check with the allow list above.
- A CI job builds and tests the workspace with the test provider only.
- Every rule and table carries a `sources` field validated at pack build;
  the generated reference marks rows that await a text.
- `docs/01-research/feature-universe/19-verification-cruxes.md` is the
  public register of open discrepancies.

Concerns about provenance are reported like any other defect, through the
issue tracker, or privately through the channel in `SECURITY.md` if the
concern involves a licence.
