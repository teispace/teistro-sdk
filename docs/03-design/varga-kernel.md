# The varga kernel

Status: `draft`, 2026-09-04. The falsification pass for ADR-0017 on
divisional charts. Implemented in Phase 4, before the dasha kernels: it
has no seed, no balance and no recursion, and its test space (12 signs
times N parts) is enumerable for every chart.

## Verdict

There is one evaluator:

```
varga_sign(sign, part) = table[sign][part]
```

with `table` generated from four parameters or supplied explicitly, and
`part` from a span rule. Of the baseline engine's 21 charts, 18 are
generated by a linear rule; three (D2 Hora, D5 Panchamsha, D30
Trimshamsha) supply their table explicitly; D30 alone also needs unequal
spans. No chart needs code of its own, including arbitrary D-N and the
named variant schemes. PyJHora arrived at the same parameterisation
independently (`custom_divisional_chart` builds a `[12][N]` table from a
base sign, a grouping method and a divisor), which is the strongest
available evidence that it is the right one.

## Deriving the single form

Write `s` for the sign index, `p` for the part index within the sign.
The baseline engine's formulas (`varga-formulas.data.ts`) normalise to
one shape:

| chart | rule as written | normalised |
|---|---|---|
| D1 | `s` | `(1·s + 0·p) mod 12` |
| D3, D4 | `s + part × 4`, `s + part × 3` | `(1·s + 4·p)`, `(1·s + 3·p)` |
| D12, D60, D150 | `s + part` | `(1·s + 1·p)` |
| D9 | from the global longitude | `(9·s + 1·p)` |
| D7, D10, D11 | odd signs from the sign, even from the 7th, 9th, 11th | `(1·s + p + [0, 6 or 8 or 10][s mod 2])` |
| D6, D40 | odd from Aries, even from Libra | `(0·s + p + [0, 6][s mod 2])` |
| D24 | odd from Leo, even from Cancer | `(0·s + p + [4, 3][s mod 2])` |
| D8, D16, D45 | movable, fixed, dual from Aries, Leo, Sagittarius | `(0·s + p + [0, 4, 8][s mod 3])` |
| D20 | movable, fixed, dual from Aries, Sagittarius, Leo | `(0·s + p + [0, 8, 4][s mod 3])` |
| D27 | by element | `(0·s + p + [0, 3, 6, 9][s mod 4])` |
| D2 | Leo and Cancer only, by parity | explicit table |
| D5 | odd `[0, 10, 8, 2, 6]`, even `[1, 5, 11, 9, 7]` | explicit table |
| D30 | spans 5, 5, 8, 7, 5 degrees, mirrored for even signs, irregular targets | explicit table plus a span table |

So the unified form is `(a·s + b·p + offset[classifier(s)]) mod 12`, and
an explicit table subsumes it (any linear rule can be materialised).
There is no second family, only two ways to populate one table.

## Schema

```rust
pub struct VargaDef {
    pub id: VargaId,                 // D1..D300 or a named variant key
    pub divisions: u16,              // N, 1..=300
    pub spans: SpanRule,             // Equal | Explicit(Vec<Ratio>)   (sum to 30 degrees exactly)
    pub map: VargaMap,
    pub sources: Vec<Citation>,
    pub confidence: Mark,
}

pub enum VargaMap {
    Linear { a: SignMultiplier, b: u8, classifier: SignClassifier, offsets: Vec<u8> },
    Explicit(Box<[[u8; 12]]>),       // [classifier group][part] or [sign][part]
}

pub enum SignMultiplier { Base /* a = 0: count from a fixed sign */, FromSign /* a = 1 */, Cyclic /* a = N: parivritti */ }
pub enum SignClassifier { None, Parity, Modality, Element }
```

Both variants compile at load into the same `[12][N]` table of sign
indices; evaluation is `part_index(deg_in_sign, spans)` followed by one
lookup. The part index is exact integer arithmetic on `Nas`
(`exact-arithmetic.md`): the baseline engine computes it as
`floor(deg / (30/N))` in floating point, and none of 30/7, 30/11, 30/27 or
0.2 is representable, so a planet at a part boundary can land on either
side depending on the platform. For D30's unequal spans the same rule
applies against a cumulative span table in `Nas`.

## Named variants as rows

| variant | how it is a row | mark |
|---|---|---|
| parivritti (cyclic) charts | `a: Cyclic` | T |
| even-sign reversal | a reversal flag over the offset table | T |
| Hora schemes: Parashara, Raman, Kashinath, three parivritti forms | six rows differing in the offset table | T |
| Drekkana: Parashara, Jagannatha | two rows | T |
| Navamsa: Kalachakra variant | a row | T |
| count from the end of an even sign | a fifth parameter of uncertain definition (a third-party implementation marks its own as not matching reference software); registered, unimplemented | S |

**Arbitrary D-N does not "fall out".** There is no classical rule for
D37. Producing one requires a chosen convention (cyclic parivritti is the
usual default), so the request names the convention or receives the
profile's default, and the result carries it in provenance (ADR-0020).

## Invariants asserted over the whole table

1. `spans` sum to 30 degrees exactly for every chart (catches D30
   transcription errors).
2. `offsets.len()` equals the classifier's cardinality (1, 2, 3 or 4).
3. Every generated table entry is in 0 to 11.
4. For every chart, all 12 signs times N parts: the linear form and its
   materialised table agree.
5. D1 is the identity.
6. Vargottama (`table[s][p] == s`) is detectable uniformly.
7. For `Cyclic`, the 12·N cells cover the 12 signs evenly (the defining
   property of parivritti).
8. The part index is computed in integer arithmetic; the float path is
   unrepresentable in the type.

## Tests and golden vectors

Exhaustive generation per chart (invariant 4); golden vectors from spike
1 for all 21 baseline charts on 50 charts; boundary fixtures at every
part boundary for D7, D11, D27, D150 and every D30 span edge; PyJHora
cross-checks for D81, D108, D144 and the named hora variants once sourced.

## Not covered here

Vimshopaka and vaiseshikamsa weights (a separate table in
`strength-schemes.md`); D30 span variants in other editions (verify);
the mixed-chart axis `(varga_for_planets, varga_for_lagna)` is a chart
context parameter (`rules-engine.md`), not a varga property.
