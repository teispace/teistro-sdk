# Teimeris data ranges

Status: generated by `cargo xtask teimeris-ranges` from `adapters/ephemeris-teimeris/rust/data/ranges.json`, which `teistro-ephemeris-teimeris-ranges` writes from the engine's full data set; held by `cargo xtask check-teimeris-ranges`. Do not edit by hand.

Every package of the Teimeris adapter carries **1800–2399** in its own binary, the engine's `MODERN` tier: `sepl_18.se1`, `semo_18.se1` and `seas_18.se1`, 2 011 836 bytes. That is what a provider reads when nothing else is named, on every platform, a phone and the web included. Any other years are a **range** an app adds: it downloads a block's files into its own storage and names them (Rust `TeimerisProvider::data().file(path)` or `.bytes(name, bytes)`; `files` in every binding's `teimeris(…)`). Each file is checked against the size and SHA-256 below before it is read, and one that differs is refused by name, which is what a download cut short looks like. A set with a hole in it (a block missing between two others, or a planet block without its Moon) is refused with the files that fill it.

A block is two files an app needs, the planets' (`sepl`) and the Moon's (`semo`), and a third, the asteroids' (`seas`), read only for a chart that names Chiron, Ceres, Pallas, Juno or Vesta. The files are the Swiss Ephemeris's own, which the engine reads unchanged; on 2026-10-20 every name and size here was found in that distribution's `ephe` directory (github.com/aloistr/swisseph), and three files' digests were checked byte for byte.

51 blocks, 153 files. Their needed files weigh 97 953 493 bytes in all (97.95 MB), and with the asteroids' 109 224 673 bytes (109.22 MB).

The years are those the blocks' names give. The earliest and the latest hold less: the first block's files begin at JD -3026605.5 (about 13000 BC) and the last's end at JD 7929133.5 (about 16996), and a provider holding either claims only that.
