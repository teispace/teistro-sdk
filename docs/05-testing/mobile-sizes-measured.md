# Mobile sizes

Status: generated by `cargo xtask mobile-sizes` from `mobile-sizes.json`, which `cargo xtask measure-mobile` records; held by `cargo xtask check-mobile-sizes`. Do not edit by hand.

What each mobile slice weighs, in bytes, for the three libraries an app chooses between. **The SDK library** is the slice the release ships, the built-in ephemeris inside it. **Without the built-in** is the same library built with `--no-default-features --features full`: every module family, no ephemeris of its own, the one an app that plugs a real engine in bundles. **The Teimeris adapter** is `adapters/ephemeris-teimeris/rust` with Teimeris's `MODERN` data compiled in, so it needs no data file. **On Teimeris** is the sum an app on Teimeris bundles, the second and the third; the last column sets it against the SDK library alone.

Each library is cross-built the way the release builds its slice (`xtask/src/mobile.rs`) and held to the same floor before it is measured: the ELF machine, Bionic's libraries alone and 16 KB pages on Android, the platform and deployment target on iOS. It is measured twice. **As built** is the file Cargo writes, the slice the release ships. **Stripped** is what an app's build makes of it, held to the same floor again: on Android the Gradle plugin strips every native library (the NDK's `llvm-strip --strip-unneeded`), and on iOS the local symbols are removed (`strip -x`). Every symbol the loader resolves stays. Read back from a Flutter release build on 2026-10-20 (`adapters/ephemeris-teimeris/flutter/example`): an APK stores both libraries uncompressed at exactly their stripped size here, and an iOS release app's framework is already stripped as far, larger only by the code signature its build adds (about 140 KB on the SDK library).
